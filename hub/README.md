# アイデアハブ(スプレッドシートとの同期)

idea-box のカードを自分のGoogleスプレッドシートに置いて、iPhone・PC・Chrome拡張・iOSショートカットの間で共有するための受け口です。費用はかかりません。

- アプリのデータは今まで通り各端末の中にあり、開いたときと、書いてから数秒後に、変わった分だけをやり取りします。
- 同じカードを二つの端末で直したときは、後から直したほうが残ります。削除も伝わります。

## 準備(最初の1回、パソコンで行うのが楽です)

1. Googleドライブで新しいスプレッドシートを作ります(名前の例: アイデアハブ)。
2. メニューの「拡張機能」→「Apps Script」を開きます。
3. 最初からある `コード.gs` の中身を全部消して、[Code.gs](https://raw.githubusercontent.com/tadamasa/idea-box/main/hub/Code.gs) の中身を貼り、保存します。
4. 上の関数の選択欄で `setup` を選び、「実行」を押します。
   - 権限の確認が出たら、自分のアカウントを選び、「詳細」→「(安全ではないページ)に移動」→「許可」と進みます。自分で作ったスクリプトなので問題ありません。
   - 下の実行ログに「合言葉: …」と「投稿用合言葉: …」が出ます。どちらも控えます(投稿用合言葉は、下の「他のAIから受信箱へ投稿するとき」で使います)。
5. 右上の「デプロイ」→「新しいデプロイ」を開き、種類の歯車から「ウェブアプリ」を選びます。
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**
   - 「デプロイ」を押し、出てきた「ウェブアプリのURL」(`…/exec` で終わるもの)をコピーします。
6. idea-box の「設定」→「アイデアハブ」に、URLと合言葉を入れて「接続して同期する」を押します。
7. PCのブラウザでも同じアプリ(https://tadamasa.github.io/idea-box/)を開き、同じURLと合言葉で接続します。
8. Chrome拡張(`extension/README.md`)とiOSショートカット(`docs/shortcuts.md`)にも、同じURLと合言葉を入れます。

URLと合言葉を知っている人は読み書きできるので、他の人には教えないでください。

## スクリプトを新しくするとき

Code.gs を貼り替えて保存したら、「デプロイ」→「デプロイを管理」→ 鉛筆の印 → バージョン「新バージョン」→「デプロイ」。URLは変わりません。

投稿用合言葉(`CAPTURE_TOKEN`)が入る前からハブを使っている場合は、新バージョンをデプロイしたあとに一度 `setup` を実行してください。実行ログに「投稿用合言葉: …」が出ます。いまの合言葉は変わらないので、アプリ・Chrome拡張・iOSショートカットの設定はそのままで動きます。

新しい権限が必要になった版(たとえば、ページの見出しを取りに行く「外部サービスへの接続」)では、保存したあとに一度 `setup` を実行して許可してから、新バージョンをデプロイします。

## 他のAIから受信箱へ投稿するとき

他のAI(保管庫に合言葉を預けて使うものなど)には、いつもの合言葉ではなく **投稿用合言葉** を渡します。URLに付けて送り、本文には `capture` だけを入れます。

```
POST {ハブのURL}?token=<投稿用合言葉>
Content-Type: text/plain;charset=utf-8

{"capture": {"text": "テスト", "source": "muse"}}
```

`{ "ok": true, "id": … }` が返れば、受信箱にカードが1枚できています。

- 投稿用合言葉でできるのは、受信箱への投稿(capture)だけです。カードの読み取り(同期)や見出しの問い合わせ、本文に `capture` 以外を混ぜた送信は `unauthorized` で断ります。
- URLに付けた合言葉は Apps Script の実行ログなどに残ることがあります。分けてあるので、漏れても影響は受信箱への投稿に限られます。
- 投稿用合言葉だけを作り直す(または止める)には、Apps Script の「プロジェクトの設定」→「スクリプト プロパティ」で `CAPTURE_TOKEN` を消します。消したままなら投稿用合言葉では何も通らず、`setup` を実行すれば新しい値ができます。いつもの合言葉(`TOKEN`)は変わりません。
- 投稿用合言葉は本文の `token` に入れても通りません。いつもの合言葉をURLに付けても通りません。

## シートの中身

シート `cards` に1行1カードで入ります。主な列は kind(種類)、title、tags(タグ名をカンマ区切り)、inbox(受信箱にあるか)、action・due・done(アクション)、url、createdAt です。

- `deleted` が `true` の行は削除済みです。
- タグもカードの一種で、kind が `tag` の行です。
- 最後の `json` 列がアプリの元データです。表を手で書き換えても、アプリには反映されません。
- 写真そのものは入りません(読み取った文字だけが入ります)。

## URLを送ったとき

URLが届くと、ハブがそのページを読みに行き、代表画像(og:image)をカードのサムネイル用に残します。タイトルなしで届いたときは、見出しも本文の先頭に入れます。

- X(旧Twitter)のポスト: 公式の oEmbed(publish.twitter.com)から、ポストの文と投稿者名を取ります。
- YouTube: oEmbed から、動画の題名とチャンネル名を取ります。
- そのほか: ページの og:title(なければ `<title>`)と、og:image(なければ twitter:image)を取ります。画像は https のものだけ使います。

取れなかったときは何も足さず、受け取り自体はいつも通り成功します。Chrome拡張(0.2.0以降)は開いているページの代表画像も一緒に送るので、そのときは読みに行きません。

アプリで直接入れたURLカードは、アプリがハブに `{ token, meta: URL }` を送って、代表画像と見出しを問い合わせます(アプリからは他のサイトを直接読めないため)。1回に30件までで、一度問い合わせたカードには `imageTried` の印が付きます。この問い合わせは新しい Code.gs が必要なので、更新したら「デプロイを管理 → 新バージョン」で出し直してください。古いハブのままでも、問い合わせをやめるだけで何も壊れません。
